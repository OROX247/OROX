# Lessons learned (append, newest at the bottom)
- three.js r128 has no userData on textures. Track shared textures in a Set.
- Many point lights make shader compiles freeze the page. Use emissive materials plus glow sprites instead.
- Live AI video cannot give solid ground: it repaints every frame and the world swims. Use real textures on real geometry.
- Newer Decart models report fps as an object ({ideal, max}); read the number before calling captureStream.
- The published claude.ai link blocks outside services. Anything that calls Decart or Poly Haven must run from the local file.
- Testing: the game script is wrapped in an IIFE, so page.evaluate cannot see travel/state/p. Test an instrumented copy in the scratchpad (add `window.__ev = s => eval(s);` before the final `})();`); never edit index.html for tests.
- Testing: in headless Chromium with SwiftShader, scene.environment (the PMREM env map) turns every MeshStandardMaterial black, in every commit. Set scene.environment = null before test renders; this is a test-only workaround, not a game bug.
- Testing: SwiftShader runs at about 1-2 fps, so degrade() lowers quality mid-test and the frame loop can lag behind travel(). Set fSkip = 1e9 to freeze quality, and wait for frames before comparing screenshots, or the "same" view will look different.
- Procedural tiling textures: every sine/stripe must complete a whole number of cycles across the tile in both axes (e.g. phase (22x + 5y)/S), or a seam shows. Warp them only with an already-tileable field.
- A realm's fixed look breaks if anything in its build uses Math.random (rock tints did). Use rng(seed) for anything that is drawn.
- Testing hooks are built in now: `window.__hub` exposes state, p, cam, post, stats, scene, renderer, travel, buildWorld, startGame, degrade, freezeQuality() and gl (the renderer string). No instrumented copy needed. The game detects software GL (SwiftShader) itself and skips scene.environment, so headless screenshots are lit.
- Picture quality lives in one place: the post-processing section (`setupPost`): 4x MSAA -> half-res SSAO multiplied in -> bloom (threshold 0.92, glows only) -> gamma -> grade (vignette) -> SMAA. The composer renders in linear space, so the GammaCorrection pass is required; without it the picture is dark. Shadows render once per frame (`renderer.shadowMap.autoUpdate = false`, flagged in frame()), so any extra renderer.render call must not expect a fresh shadow map.
- Bloom on bright diffuse surfaces (sand, sky horizon) reads as haze. Keep the threshold above 0.9 so only emissive glows and the sun bloom.
- The quality ladder (`degrade`) drops effects first: SSAO, bloom, shadow resolution, grass, then pixel ratio to 1. It never disables shadows and never goes below pixel ratio 1.

- Avatars are recipe-driven (blueprint 5a): `parseDescription(text)` -> recipe -> `makeAvatar({recipe, name})`. Add a species to SPECIES, a word to WORD_FEATURES/WORD_MATERIALS/WORD_PATTERNS, or a feature builder inside makeAvatar; never special-case one description. `cleanRecipe` validates everything, so an AI path only has to return JSON. The player is `let me`; anything that changes the recipe calls `rebuildPlayer()`.
- Non-uniform group scale (height vs build) is fine for meshes but stretches sprites: divide a name-tag sprite's scale by the group scale.
- Sectors: every realm has `sector` and `rules:{magic, tech, danger}` in WORLDS; `fare(from, to)` prices warps by Chebyshev distance on the 3x3x3 cube (0 -> 10, 1 -> 25, 2 -> 60, 3 -> 120, Hub free). The star map is drawn by `drawStarMap()` from WORLDS, so a new realm only needs its sector number to appear on it.
- The shop is data: add a row to SHOP_ITEMS (feature ids come from R_FEATURES, finishes from R_MATERIALS). `state.owned` persists purchases; wearing is just the recipe.
- Health (Goal 5): `hurt(n, why)` is the only way to deal damage. It does nothing in a `danger:false` realm, while traveling, or while zeroing out, so new damage sources just call it. Fixed hazards go in `addHazards(key)` with their own `rng(seed * 31 + 7)`, called after coins and NPCs, so nothing already placed in a realm moves.
- Zero-out: everything the avatar carries is listed in `CARRY` (kind -> {take, give}). The inventory (Goal 6) adds one row and its items drop into and return from loot bundles with no other change. Bundles are session-only (not saved). Dropped gear means ownership (`state.owned`), not the worn recipe, because the avatar only changes when the player changes it. `trySecondBreath()` is the hook where The Second Breath will cancel a death.
- A toast shown right after travel() gets overwritten by the texture loader's "Loading real textures" toast. Put arrival messages on their own panel (as #zeroFx does).
- Testing: a SwiftShader screenshot takes over 2 seconds, so short timed moments (the 1.8 s zero-out) are gone before it is taken. Stretch that one timer in the test by wrapping window.setTimeout before triggering the moment.
- Sound is synthesised in the "sound" section (Web Audio, no files): `ambience(realm)` runs on every buildWorld, `sfx(name)` for one-shots (coin, shard, win, level, buy, jump, boost, warp, hit, zero, step, ui), N or the Sound button mutes and persists. The AudioContext only starts on the first pointer/key gesture, so never call sfx before that and never rely on sound for gameplay.
- Vehicles: the hoverbike section owns `bike` (one per realm, built by `buildBike(x, z)` inside a realm's BUILD). While `bike.riding`, update() runs `updateBike` instead of the walking block and mirrors the bike into `p`, so everything that reads p (coins, portals, shop, minimap) keeps working. travel() dismounts first; buildWorld resets the bike. Fuel is not charged yet (blueprint section 4 wants fuel cells).
- Testing: SwiftShader runs slower than 20 fps, so physics steps at the clamped dt (0.05 s) while anything driven by clock.elapsedTime (the Neon Grid laser sweepers) runs in real time. Hazard timing tests then tunnel or miss. Use a virtual clock through page.addInitScript: override performance.now and wrap requestAnimationFrame to add exactly 50 ms per frame. Do not call requestAnimationFrame from the test itself, because that advances the clock too. For the game: tie hazard motion to the same clamped time as the player, or low-fps players will see beams pass through them.
- Quests: the time trial is the first quest shape (a pad that starts it, ordered targets, a timer, a reward with par and best time in `state.best`). Reuse `trialStart/trialEnd/trialUpdate` as the template for quest portals (blueprint section 7); courses are data in COURSES.
- Inventory (Goal 6): an item is a row in ITEMS (name, rarity, whole-credit value, shape gem/orb/chip/coil, colour, desc, optional use()). `state.inv` is id -> count and saves; `giveItem`, `takeItem`, `sellItem`, `useItem` are the only ways to change it. A consumable only needs `use(){ ...; return true; }` and the panel shows a Use button. Rarity 'artifact' is capped at one. World pickups are `LOOT[realm]` placed by `addPickups(key)` (own rng, after hazards), remembered in `state.picked`.
- CSS `display:grid` on an id beats the `hidden` attribute. Anything toggled with `el.hidden` needs an explicit `[hidden]{display:none}` rule.
- Hazards run on `simTime` (sum of the clamped dt), not clock.elapsedTime, so they stay in step with player physics at any frame rate.
- Testing: the camera sits at player + (sin yaw, cos yaw) * dist and looks at the player, so to frame an object at (qx, qz) from the player use yaw = atan2(p.x - qx, p.z - qz) plus a small offset so the avatar does not hide it.
- Testing: under SwiftShader, Playwright's page.click on an open panel's buttons (#tabSell, #sellList button) can time out waiting for the element to be stable, even when it is the topmost element. Click through the DOM instead (page.evaluate(() => el.click())). Print intermediate results before any step that can throw, so one timeout does not lose the whole run.
- Trees are leaf cards now (`cardsGeo` + `leafTexture`): a canopy is ~90 textured quads around blob centres, normals pointing outward so lighting reads as a rounded volume, alpha-tested with a matching customDepthMaterial so shadows show leaves. Cards are marked noAO so SSAO does not see them as slabs. Any new plant should be built the same way; smooth blob spheres are what made the game look like a toy.
- The cinematic layer (C key): BokehPass depth of field with focus following the camera distance, plus grain and lens colour fringing in the grade shader. It is the first thing the quality ladder drops.
- Vending (Goal 7): what a terminal sells is data, a row in VEND (ITEMS id + whole-credit price above the item's sale value, so buy-then-sell never profits). `addVendor(key)` runs last in buildWorld (after addPickups) and has no rng: it tries the fixed spots in VENDOR_SPOTS in order and takes the first clear of colliders, platforms, portals, hazards, the bike, the trial pad and the Outfitters kiosk. Check placement only against fixed things, never coins or pickups, because those vanish once collected and the terminal would move. Each realm's look is a row in VENDOR_LOOK. E priority: dismount > mount bike > Outfitters > vending terminal; keep new kiosks at least 5 m from the others so their E radii never overlap.
- Hoverbike fuel: one tank in `state.fuel` (0..FUEL_MAX, saved), shared by the bike in every realm. It burns only in updateBike while playing; an empty tank coasts (no throttle, boost or hop) and cannot be mounted. Persist on dismount and when it runs dry, not every frame. A consumable's use() returns false with a toast when it would be wasted (full HP, full tank), so the item stays in the bag.
- Testing: never run two headless SwiftShader browsers at once; each drops to under 1 fps and frame-count waits time out. And never `pkill -f <word>` in the same bash command that contains that word: it kills its own shell.
- Testing: `el.offsetParent !== null` is always false for a position:fixed element, so it reports every .overlay panel (#vend, #shop, #inv) as hidden even when open. Check `!el.classList.contains('hidden')` or getComputedStyle(el).display instead.
- Campus (Goal 8): adding a portal (or any collider) to an existing realm changes which freeSpot tries are accepted, so every coin id and NPC after the first rejected spot shifts and saved coin progress points at different coins. Pick the spot more than 6 m from every accepted coin, NPC and pickup spot, then prove it with a before/after dump of `__hub.coins`, `npcs`, `pickups`, `vendor`, `shopKiosk`, `bike`, `trial.padPos` (the Spaceport's Campus portal sits at (26, 2.5) for this reason).
- Walls are data too: `addBox`/`aabb` push to `boxes` (yaw-only boxes). One list drives player push-out (only where heights overlap, or always with `full:true` for furniture so nobody lands inside a desk), NPC blocking, freeSpot, the minimap, and `clipCamera()` (a ray from the head to the camera, `cam:false` skips furniture). Windows are open to the eye but solid to walk into: build visual pieces and collision pieces separately. `merge()` drops UVs, so textured merged boxes go through `boxGeo(list, tileMetres)` (world-space UVs, one draw call per material).
- Zero-g volumes: `gymIn(x, z)` switches the walking block to a momentum branch (thrust, Space up, Shift down, soft bounce off pushes, ceiling from `gymCeil`). Never trap the player: the drum's collision boxes are taller than the dome, the door lintel blocks anyone floating too high, Shift always descends, and on touch screens (no Shift) a faint settle starts after 3 idle seconds. Leaving the volume hands velocity back to normal walking and gravity. Reuse this for The Drift in Neon Grid.
- The arrival camera (4.5 m in front of the return portal, camera 5.5 m behind the avatar) sat inside the portal, and its glow sprite plus depth of field flooded the screen in every realm. Portal glow and disc now fade with camera distance (update loop); keep that if arrival spots change.
- Testing: SwiftShader at 960x540 runs about 1-2 fps; a functional test with ~600 frame waits takes over 10 minutes and gets killed. Run state checks at 320x200, keep screenshots in a separate short run, and write output to a file instead of piping through tail (a cut-off log means a rerun).
- Testing: `renderer.info.render.calls` read from page.evaluate reports 1 (only the composer's last full-screen pass, because info auto-resets per render call). It is not the scene's draw count; to measure that, set `renderer.info.autoReset = false`, call `renderer.info.reset()` before one frame and read after it.
- Picture quality build 12-13 (owner's assistant): the sky is now a physical atmosphere (`ATM_GLSL`, Preetham scattering) with per-realm `atm` settings, cumulus clouds shaded by three density taps towards the sun, a real sun disc, and the same model on the CPU (`skyRadiance`) so the fog colour matches the horizon. Neon Grid keeps the old gradient (`mode` 1). Fog is patched into every material (`patchFog`): height fog with sun in-scatter, extra uniforms shared as plain objects added to every `ShaderLib` entry (plain objects survive `UniformsUtils.clone`, Vector3s do not). `SunRaysPass` (quarter-size bright mask around the sun, 3 radial blurs) feeds both the god rays and the lens flare in the grade pass; sharpening is the last pass.
- Surfaces are made on the GPU once per session (`surface(name)`: a shader draws colour + normal/roughness into two 1024 render targets; tileable via periodic noise). Never `clone()` a render-target texture: scale the geometry UVs instead. `terrainMaterial(spec)` blends four surfaces by slope, height and macro patches with distance-dependent repeat; the base layer stays `map`/`normalMap` so Poly Haven photos still replace it. `detailTex` values sit in 0.68-1.0, normalise before using it as a noise source. Two-sided cards (grass, leaves, weeds) override `normal_fragment_begin` so back faces are not lit from below. `merge()` now keeps UVs.
- The owner's PC is an AMD 680M-class laptop GPU at 3440x1265, 63 fps at quality step 0 with everything on; the game runs inside a cross-origin frame on claude.ai, so the test rig drives it with `postMessage({hub:'ctl', ...})` (camera, position, realm, HUD, stats) rather than `window.__hub`.
- Worldsmith (build 14, owner's assistant): `parseRealm(text)` turns a sentence into a realm recipe with priorities (lava beats lake, sandstorm beats storm beats rain; 'moon' means night unless 'lunar'/'no air', which mean an airless black sky); `customHeight`/`customBuild` build it from the same pieces the fixed realms use, plus water/lava planes, structures, planets, moons, aurora and weather particles. Forged realms live in `WORLDS['w:<id>']` with `custom` and `own`, are registered at load from localStorage, and `freeSpot` keeps 9 m around the spawn clear in them. The realm builder must never place anything at (0, 14).
- The game's frame on claude.ai only gets keyboard focus after a click inside it; a key that opens a panel must `preventDefault()` or its letter lands in the panel's text box.
- Water (build 15): `THREE.Water` (vendored, r128) draws the scene into a mirror. On the owner's AMD/ANGLE machine a mirror render nested inside the composer's MSAA render pass corrupted the whole frame into vertical streaks (fine in SwiftShader), so `renderMirrors()` runs every water's `onBeforeRender` once at top level before the frame's render, and `shouldRender` (a patch to Water.js) refuses the nested call for the same frame. Keep it that way for anything else that renders the scene into a texture.
- Flocks (`addFlock`), shuttles (`addShips`) and weather particles are per-realm arrays reset in `buildWorld`; they cost almost nothing (one InstancedMesh per flock, matrices updated per frame). Birds by day, bats at night, gulls over seas, butterflies over meadows.
- Build 16: the sun's shadow box is now 116 m across (2.8 cm per texel at 4096) so trees and buildings beyond 40 m still cast shadows; the grade pass has a little more contrast and vignette. NPCs that stop within 3 m of each other turn to face each other and linger, which reads as conversation for free. The Spaceport has 12 locals.
- Endless realms (build 17): the camera now sits on `vr.rig` (identity outside VR), so anything reading `camera.matrixWorld` before the render uses `camera.updateMatrixWorld()` first; `camWorld` is the camera's world position in both modes. Chunks are built through `buildParent` (mk/glow/instanced add to it when set) and record their colliders/platforms/spinners so `dropChunk` can take them back. `chunkSpot` keeps 16 m around the spawn and the portal clear. The Dreamer never calls Claude from a timer: `takeDream` asks for a new batch of eight only when the queue runs low, one call at a time, and gives up for the session on not_granted/rate_limited.
- On the owner's machine the artifact tab is often in the background (`document.hidden`), where requestAnimationFrame does not run: a stats reply with `frames` not increasing means the tab is hidden, not that the loop crashed. Open the link in a foreground tab before judging anything.
- Build 18: verified live on the owner's link: with "Use Claude" allowed once, the Dreamer's first batch came back in a few seconds (e.g. "Crimson Lighthouse | a towering red lighthouse with glowing mushrooms | Its beacon still pulses, guiding lost souls through the eternal dust storms"), and the same call now also returns six lines of local talk that replace the realm's NPC lines. "Surprise me" in the Worldsmith asks Claude for a fresh one-sentence realm when it can. The aurora lives in the sky group so it follows you across an endless realm.
- LOD (Goal 1 pass 2): `lodMesh(hi, lo, centre, d, h)` for single meshes and `lodInstanced(hiGeo, loGeo, mat, mats, cols, d, h, o)` for instanced props, both switched every frame by `updateLods()` from `camWorld` (never camera.position: the camera sits on `vr.rig`). Hysteresis: far beyond d + h, near again inside d. The far version must keep the same material and silhouette (same displacement function at fewer segments, half the leaf cards at 1.4x size); check with `__hub.lodScale = 1e6` (everything near) against 1 on a frozen frame: the image difference should be well under 1 grey level on average. Anything built inside a streamed cell (buildParent set) is recorded with its group (`e.grp`) and dropChunk filters it out, so LOD needs nothing extra from endless realms.
- Baking many static meshes into one per material keeps their look exactly as long as every part is transformed into place first (`geometry.applyMatrix4`) and the UVs are copied untouched: the normal maps in r128 use screen-space derivatives, not stored tangents, so rotation does not matter. The Hub skyline went from ~150 draw calls to 5 this way.
- Testing: to compare two render states pixel for pixel, stop the loop (`renderer.setAnimationLoop(null)`), render with `__hub.post.composer.render()` for each state and screenshot; `__hub.frame` restarts it. With the loop running, wind, flocks and the camera's easing make two screenshots of "the same" view differ by more than the change under test.
- Splitting uncommitted work into separate commits: `git apply --unidiff-zero` with hunks removed puts pure insertions in the wrong place (line numbers shift). Use a diff with 1 line of context, drop the hunks that belong to the other change, and redo mixed hunks by hand.
- Realism pass (what made the pictures look fake, in order of how much): the arrival camera framed through the back of the return portal; grass tufts drawn as rectangles of equal-height blades (flat hedge tops, dark roots) on a high-contrast streaky ground; Sky Isles as smooth inverted cones under flat grass pucks; Glass Dunes shrubs as smooth dark blobs; the Night Grove floor as a regular grid of same-size leaf dots. The rule behind all of them: anything regular (equal heights, equal sizes, perfect circles, grid-spaced dots) reads as computer-made. Vary size per element, break silhouettes, and keep the ground darker and calmer than what grows on it.
- Arrival: travel() puts you clamp(cam.dist + 2.5, 4.5, 12) m in front of the return portal so the camera stands in front of it. Tests that assumed the old 4.5 m spot must read p.x/p.z after travel instead.
- A new decoration in a built-in realm must not draw from the realm's `r` unless it replaces the exact same draws: coins, NPCs and pickups placed after it use the same generator and would move. Give tints and shapes their own rng(seed) (the dunes shrubs use rng(5151)) or make them deterministic from an index (the isles use lump() of the isle number).
- Still fake, not fixed yet (next realism pass): the Hub plaza's voronoi slabs with dark outlines read as cracked mud; Glass Dunes pillars and mesas have strong candy-stripe banding; Night Grove grass lit from straight above turns into flat blue-grey sheets under the moon; the Campus walkway pavers are uniformly clean; every realm's own name tag is large and always on screen.
- Testing (time budget): at 640x360 under SwiftShader, load plus start takes ~53 s and each travel() plus 3 frames takes ~20-40 s, so a sweep of all six built-in realms uses ~220 s of the 5-minute cap by itself. Do the feature checks (LOD positions, arrival camera, the one screenshot) first and the realm sweep last, or split them into two runs, and write output to a file line by line so a timeout still leaves results.
- No boundaries (Goal 8a): a built-in realm goes endless through one entry in `ENDLESS[key]`: `core` (nothing new inside it), `home` (inside it the ground disc is restored from a saved copy, so the core's ground is bit-for-bit the original), `kit()` (shared materials and geometries: `shareMat`/`shareGeo`, never disposed by dropped cells), `big(cx, cz, q)` (big footprints fixed per cell before anything else, so neighbours keep clear), and `tiers` [{name, r, build}] widest first; a `dream` tier is slotted in by radius. Optional hooks: `start`, `tick`, `solidAt`, `landAt`, `minimap`, `noRecenter`. A tier gets its own rng (`cellSeed(key, cx, cz, tier)`), starts from the spots the tiers before it took, and may only read pure functions of coordinates (G, hf, slopeAt, memoised footprints), never Math.random, time, or the order cells were built in; then a tier rebuilt later is identical and `__hub.cellSum()` matches.
- Anything the height function needs (pools, pads, campus lawns) must be a pure, memoised function of cell coordinates built from a base height, not from G: the core's ground disc evaluates hf out to 900 m when the realm is built, before any endless state exists. Keep every new height term beyond the realm's far hand-made props and its fog, because the disc's far rings are part of the view from the core.
- Far hand-made props that were only scenery (dunes mesas, hub skyline, campus far halls, sky far isles) are recorded in `coreSolids` during BUILD (no rng draws) and made solid in `startBuiltin`, after coins, NPCs, pickups and the vendor were placed, so nothing in the core moves. A platform may carry `rAt(y)` for a sloping solid (mesa apron).
- Cost of endless land (measured): InstancedMesh is never frustum-culled in r128, so the core's grass, trees and rocks were still drawn 1 km away; they now get a bounding sphere and move to layer 5 beyond the fog (2 / fog density). Cell groups behind the camera beyond two cells, or beyond the fog, are hidden; only the 3x3 cells round the player cast shadows and take part in SSAO; sprites cost one draw each, so a cell's glows are one `glowCloud` Points draw. Result 1 km out: fewer draw calls and triangles than in each core.
- Tier jobs: a job whose lower tiers are missing builds one tier per step and goes back to the front of the queue. The first version returned after building the prerequisite, so the top tier of a new cell was only built after the next cell change (the sort order put a tier's job before its prerequisite's).
- Streaming budget: at most 3 ms a frame and at least one step; one step is one tier of one cell (keep it under ~5 ms: the heavy shapes are made with the realm, inside the travel fade, grass is its own step, and grass, weeds and pebbles read heights from a 2 m table per cell). Re-centring the ground disc costs ~90 ms in total and runs in slices on a 24 m lattice. `instanced()`/`lodInstanced()` with an empty list must not dispose shared kit pieces.
- Testing endless realms: `__hub.teleport(x, z)` (lands on the nearest isle in Sky Isles) plus `__hub.streamNow()` builds everything at once; waiting for SwiftShader frames to drain a queue of 300 far cells takes minutes. `__hub.coreSum()` hashes lodInstanced entries by their full instance list (the near/far split depends on where the camera is) and skips bobbing things (shard, spinners, coins, NPCs). `__hub.bigsNear(n)` lists mesas, pads, towers, pools and campuses round the player.
- Testing: `pkill -f "node t1.js"` inside a bash command kills that same shell (its command line contains the pattern). Use a bracket in the pattern: `pkill -f "node [t]1.js"`. And check `pgrep` before starting a second browser: two SwiftShader runs writing one output file lost a run.
- Testing speed: under SwiftShader, anything that waits for frames is slow in the heavy realms (Night Grove renders at well under 1 fps at 1 km, so a 60-frame walk took minutes). For state checks, build the realm with `__hub.buildWorld(key)` instead of travel, move with `teleport` + `streamNow`, and run physics without rendering: stop the loop, set `keys`, call `__hub.update(0.05, t)` N times, restart with `renderer.setAnimationLoop(__hub.frame)`. The Goal 8a check of all six realms then takes ~2.5 minutes including one screenshot.
- Planets (Goal 8b): a star is `sectorStars(n)[i]` (sectors 2-27, 12-40 each, seeded by the sector number, spaced so each can be clicked). Its seed comes from its coordinates (`starSeed`), and `rollPlanet` turns that seed into a Worldsmith sentence plus three numbers the words cannot carry (gravity 0.55-1.4, relief, plant size). The sentence goes through `parseRealm` and the forged-realm builder like anything the player types, so a new planet feature is a new word in the roll, not new building code. `planetWorld(id)` registers `WORLDS['p:<id>']` on demand; `rec.relief`/`rec.flora` default to 1 so forged realms are unchanged.
- Words in a generated sentence must be checked against every WS_WORDS table, not only the one you mean: "amber leaves" set the ground to forest floor ('leaves' is a surface word), 'meadow' is also a terrain word, 'golden' means sunset, 'grey' means overcast, 'deep' means dense, 'stars' means night and 'planet' adds a ringed planet to the sky. The parser takes the last match, so put the word that must win last ("hills of snowy ground"). Colour a thing with a word that is only a colour target ("foliage", "sky", "ground", "water").
- When a generator rolls optional parts, make every draw even when the part ends up skipped (roll the chance and the pick, then decide whether to use them), or fixing one case shifts every later roll and changes other planets: dropping "foliage" for treeless planets first skipped a pick() and turned a dangerous planet peaceful. Charting stores the rolled sentence and numbers (`explorer.planets[id].spec`), so a planet already seen never changes even if the generator does.
- Object.assign copies a getter's value once; to add live getters to `window.__hub` after it is built, use Object.defineProperties (the first explorerLog hook always returned the empty list from load time).
- Planet landmarks: whether a cell has one, where, and its shape use their own seeds (`planetDream`), never the cell's main rng, so a Claude-named landmark and an offline one leave the rest of the cell identical. What the landmark is gets stored per cell in hub-dreams-v1 under the planet key the first time it is built.
- Safe arrival: a planet's WORLDS entry has a pad at (0, -19) r 10 (pads flatten the height to 0 through `pf`, and every water, lava and acid level is below 0), `chunkSpot` keeps 14 m round it clear, and `safeLanding()` walks outward to dry, gentle ground if anything ever sits wrong. Lava 17 m from the pad is fine: it is visible, and it only burns (through hurt()) on danger planets.
- The forged-realm streaming re-centred the ground disc and refilled the grass in one step every 42 m (30-170 ms under SwiftShader). Planets use the built-in realms' sliced `reJob`/`reStep` plus a sliced `grassStep` (`planetStream`, 3 ms budget), cast shadows only from the 3x3 cells round the player and hide cells outside the view beyond one cell. Forged realms still re-centre in one step; switching them over is a small follow-up.
- Testing planets: `await __hub.landOn(id)` resolves on arrival with `{dry, water, gravity, ...}`; `__hub.planetSum()` right after landing hashes the spec, a 21x21 height grid and the whole built world (NPCs, flocks and spinners skipped), so two visits compare with one JSON string. Three planets twice plus a reload take ~230 s at 640x360.
- Testing screenshots: a test that must show something specific (the planet return beacon, a pad) has to aim the camera at it before the shot (set yaw with the atan2 rule above, or use a debug camera hook). After landOn() the camera keeps whatever yaw it had, and the Goal 8b shot of Lumez faced a dark cliff with the beacon only on the minimap. Also at 640x360 the button bar sits across the player name tag in the middle of the screen.
